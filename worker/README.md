## Setup and redeployment

The resources above already exist. For routine redeployment, use the existing configuration and secret; run `npm ci`, `npx wrangler d1 migrations apply the-remote-beta-requests --remote` and `npx wrangler deploy --strict` from `worker/`. Do not create duplicate resources or new credentials. The steps below record the initial setup procedure.

1. Sign in to the existing Cloudflare account in Brave. Verify `baagad.ai@gmail.com`, the intended account, Workers paid plan and existing resources before changes. Passwords, CAPTCHA, security challenges and new agreements belong to the user.
2. `npm ci` in `worker/`. `npx wrangler whoami` is read-only. Before a new OAuth/API token or persistent access grant, show the requested account and exact scopes and obtain action-time approval. Do not read browser sessions or print token values. Wrangler's default login scopes may be broader than this project needs; inspect `wrangler login --help` and `wrangler login --scopes-list` first. The minimum sensible setup grant is `account:read user:read workers_scripts:write d1:write challenge-widgets.write`; Wrangler automatically adds `offline_access` and stores refresh credentials. These permissions cover resources beyond this single project. Omit broad `workers:write`, KV, routes, Pages and zones scopes. After approval, use `wrangler login --browser=false --scopes account:read user:read workers_scripts:write d1:write challenge-widgets.write` and open only the generated Cloudflare authorization URL explicitly in Brave for the user to review and approve. If workers.dev registration requires a new agreement, pause for the user.
3. After verified account access, create D1 `the-remote-beta-requests` with `npx wrangler d1 create the-remote-beta-requests`. ## Private CSV export

Run `node worker/export.mjs <private-absolute-path.csv>` from the repository root. The CLI uses the Cloudflare D1 API directly, keeping result data out of Wrangler logs. Supply `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_DATABASE_ID` through private environment configuration, never command-line token arguments. A new token requires action-time approval; scope it to D1 Read on the verified account. The official D1 query API accepts D1 Read; verify the effective token permissions before use. The tool executes only fixed SELECT SQL.

Output is UTF-8 without BOM, one validated normalized email per line, no header. It resolves parent-directory aliases and refuses paths inside this repository and refuses to overwrite existing files; use a private non-synced folder with appropriate Windows ACLs. It prints only a count, never addresses or raw API errors. The tool reads all current requests in sorted pages; concurrent signups may require another export. Delete private exports when no longer needed.

**Uploading a CSV in Google Play replaces the selected tester email list.** Review and preserve existing testers before any list upload; this export command does not upload, invite or enroll anyone. After review, add approved accounts manually to the correct Google Play test and send invitations there. Delete D1 records when no longer needed or when an authenticated owner handles a deletion request. D1 backups may retain removed records under Cloudflare's backup policy.
